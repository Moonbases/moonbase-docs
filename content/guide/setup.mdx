Moonbase has two `.env` files: `api/.env` for the API and `app/.env` for the storefront and dashboard. The installer creates both from their `.env.example` files on its first run.

<Callout type="error" title="Never share or commit your .env files">
  They hold the keys that encrypt your data and sign every session. Back them up with your database instead.
</Callout>

## API settings (`api/.env`)

The API reads `.env` from the folder it starts in (`api.bat` and `api.sh` start it in `api/`). Variables set in the real environment, for example by systemd or PM2, take precedence over the file.

When a value is missing or invalid, the API stops with `Invalid environment configuration` and lists each problem.

### Required

| Variable | What to set |
| --- | --- |
| `PORT` | Port the API listens on. The example uses `80`. |
| `URL` | Public URL of the API, e.g. `https://api.example.com`. Used for download links and payment provider callbacks. |
| `CLIENT_URL` | Public URL of the storefront, e.g. `https://store.example.com`. Used for redirects and links in emails. |
| `MONGO_URI` | MongoDB connection string, including the database name. |
| `ENCRYPT_KEY` | Encrypts license keys and secrets in the database. Generated by the installer. **Keep it forever.** |
| `JWT_SECRET` | Signs sign-in sessions and download links. Generated by the installer. Changing it signs everyone out. |

The API refuses to start while `ENCRYPT_KEY` or `JWT_SECRET` still has the example value (`replace_with_random_…`). See [Security](/docs/guide/security#encrypt_key-and-jwt_secret).

### First start only

| Variable | What to set |
| --- | --- |
| `APP_EMAIL` | Email of the owner account. |
| `APP_USERNAME` | Username of the owner account. |
| `APP_PASSWORD` | Password of the owner account. |

These three create the owner account the first time the API starts. Remove them afterwards.

### Payments

Configure only the providers you use. A provider is offered at checkout only when all of its values are set.

| Variable | What to set |
| --- | --- |
| `STRIPE_SECRET_KEY` | Your Stripe secret key. |
| `STRIPE_WEBHOOK_SECRET` | Signing secret of your Stripe webhook endpoint. |
| `COINBASE_COMMERCE_API_KEY` | Coinbase Commerce API key. |
| `COINBASE_COMMERCE_WEBHOOK_SECRET` | Coinbase Commerce webhook shared secret. |
| `PAYPAL_CLIENT_ID` | Client ID of your PayPal REST app. |
| `PAYPAL_CLIENT_SECRET` | Secret of your PayPal REST app. |
| `PAYPAL_MODE` | `sandbox` (default) for testing, `live` for real payments. |
| `PAYPAL_WEBHOOK_ID` | ID of your PayPal webhook. Required: PayPal webhooks are rejected without it. |

Each provider has its own page with the webhook URL and events: [Payments](/docs/guide/payments).

### Email (SMTP)

| Variable | What to set |
| --- | --- |
| `EMAIL_FROM` | Sender, e.g. `"Moonbase <no-reply@example.com>"`. |
| `EMAIL_HOST` | SMTP server. Leave it empty to turn email off. |
| `EMAIL_PORT` | SMTP port. Defaults to `587`; `465` always uses TLS. |
| `EMAIL_USER` | SMTP user name, if your server needs one. |
| `EMAIL_PASSWORD` | SMTP password. |
| `EMAIL_SECURE` | `true` to connect with TLS from the start. |

Email powers account confirmation, password resets, product access and expiry emails, receipts, release announcements, ticket replies, guest checkout and checkout reminders.

<Callout type="warn" title="No SMTP server? Clear EMAIL_HOST">
  The example file sets `EMAIL_HOST=localhost`, so Moonbase treats email as configured. If you don't run an SMTP server there, emails fail silently and features that need email stay switched on. Leave `EMAIL_HOST` empty instead.
</Callout>

### Discord

| Variable | What to set |
| --- | --- |
| `USE_DISCORD_BOT` | `true` to run the Discord bot. When it is not set, the bot runs whenever `TOKEN` is set. |
| `TOKEN` | Bot token. |
| `CLIENT_ID` | Application ID of the bot. |
| `GUILD_ID` | ID of the Discord server the bot works in. |
| `DISCORD_OAUTH_CLIENT_ID` | Application ID used for "Sign in with Discord" (the one in `NEXT_PUBLIC_DISCORD_CLIENT_ID`). Defaults to `CLIENT_ID`. Discord sign-in is off when neither is set. |

### Optional

| Variable | Default | What it does |
| --- | --- | --- |
| `TRUST_PROXY_HOPS` | `0` | Number of reverse proxies in front of the API. See [Reverse proxy](/docs/guide/operations#reverse-proxy). |
| `DNS_SERVERS` | `1.1.1.1,8.8.8.8` | DNS servers for `mongodb+srv://` lookups, comma separated. `system` uses your operating system's resolver. |
| `STORAGE_DIR` | `./storage` | Folder for uploaded files and product images. |
| `PLUGINS_DIR` | `./plugins` | Folder with backend plugins. |
| `WEBHOOKS_ALLOW_PRIVATE_NETWORKS` | `false` | `true` lets [outgoing webhooks](/docs/guide/features/webhooks) reach `localhost` and your LAN. |
| `PASSWORD_BREACH_CHECK_STRICT` | `false` | `true` refuses new passwords while the breached-password check (Have I Been Pwned) can't be reached. By default they are accepted with a warning in the API log. |

## App settings (`app/.env`)

| Variable | What to set |
| --- | --- |
| `NEXT_PUBLIC_API_URL` | Public URL of the API, the same as `URL` in `api/.env`. **Compiled in:** run the installer again after changing it. |
| `PUBLIC_API_KEY` | Public API key printed on the API's first start. |
| `PRIVATE_API_KEY` | Private API key printed on the API's first start. It also signs each visitor's IP address for the API. |
| `TRUST_PROXY_HOPS` | Number of reverse proxies in front of the **app**. Default `0`. See [Reverse proxy](/docs/guide/operations#reverse-proxy). |
| `NEXT_PUBLIC_DISCORD_CLIENT_ID` | Discord application ID. Shows "Sign in with Discord" when set. Compiled in. |
| `NEXT_PUBLIC_DISCORD_REDIRECT_URI` | Where Discord sends users back, e.g. `https://store.example.com/auth`. Add it to the redirects of your Discord application (OAuth2 page). Compiled in. |

Changing `PUBLIC_API_KEY`, `PRIVATE_API_KEY` or `TRUST_PROXY_HOPS` only needs an app restart. Changing a `NEXT_PUBLIC_*` value needs a rebuild: run the installer again.

<Callout type="info" title="Store name and branding are not in .env">
  `NEXT_PUBLIC_NAME`, `NEXT_PUBLIC_DESCRIPTION` and `NEXT_PUBLIC_DISCORD_INVITE` from 1.x are no longer read. Set the store name, description, logo, support email and Discord invite in **Dashboard → Store settings** (see [Store settings](/docs/guide/features/store-settings)).
</Callout>

## First start

<Steps>
  <Step>
    ### Start the API

    <Tabs items={['Windows', 'Linux']}>
      <Tab>
        ```bash
        api.bat
        ```
      </Tab>
      <Tab>
        ```bash
        bash api.sh
        ```
      </Tab>
    </Tabs>

    Wait for `API is now ready to use on port …`.
  </Step>
  <Step>
    ### Save the API keys

    On the first start the API creates the owner account from the `APP_*` values and prints two keys under `FIRST STARTUP API SECRETS (SAVE THESE NOW)`:

    ```text
    Public Api Secret:  …
    Private Api Secret: …
    ```

    They are shown **only once**. Copy both into `app/.env`:

    ```dotenv
    PUBLIC_API_KEY=your_public_key
    PRIVATE_API_KEY=your_private_key
    ```
  </Step>
  <Step>
    ### Remove the owner bootstrap values

    Delete `APP_EMAIL`, `APP_USERNAME` and `APP_PASSWORD` from `api/.env`. Do **not** remove `ENCRYPT_KEY`.
  </Step>
  <Step>
    ### Start the app

    <Tabs items={['Windows', 'Linux']}>
      <Tab>
        ```bash
        app.bat
        ```
      </Tab>
      <Tab>
        ```bash
        bash app.sh
        ```
      </Tab>
    </Tabs>

    By default the API runs on `http://localhost:80` and the app on `http://localhost:3000`.
  </Step>
  <Step>
    ### Sign in and set up the store

    Sign in with the owner email and password. The dashboard overview shows a setup guide with the next steps. Start with **Dashboard → Store settings**: store name, description, logo, brand color, currency, support email and Discord invite. See [Store settings](/docs/guide/features/store-settings).
  </Step>
</Steps>

<Callout type="warn" title="Before you go live">
  Run both processes under a process manager behind an HTTPS reverse proxy, set up your payment webhooks and test a sandbox purchase. See [Operations](/docs/guide/operations) and [Payments](/docs/guide/payments).
</Callout>
