Frontend plugins are React code compiled into the storefront and dashboard (the Next.js app). The runtime lives in `app/lib/plugins` and runs in the browser. Plugin code lives in `app/plugins` and is listed in `app/plugins/registry.ts`.

## Lifecycle
<Steps>
  <Step>`PluginHost` (`app/lib/plugins/PluginHost.tsx`) wraps every page from the root layout `app/app/layout.tsx`. It renders the `global` slot and the `mounts` portals after the page content.</Step>
  <Step>`PluginProvider` reads the registry once, drops plugins whose `enabled` is `false` (or returns `false`), and builds the shared `ctx` (API, storage, events, route, checkout, logger).</Step>
  <Step>After the first render in the browser, each plugin's `bootstrap(ctx)` runs once, in registry order. A function it returns runs when the app unmounts.</Step>
  <Step>Slots, mounts and pages render with `{ ctx, plugin }` as props.</Step>
</Steps>

## Registration
Add each plugin to the registry so the runtime can pick it up:

```ts
// app/plugins/registry.ts
import type { FrontendPlugin } from '@/lib/plugins/types';
import myPlugin from './my-plugin';

export const plugins: FrontendPlugin[] = [myPlugin];
```

The list order is the order of slots, pages and `bootstrap` calls. Mounts are ordered by their `order` value.

<Callout type="info" title="Rebuild after changes">
  Frontend plugins are part of the app build. In a source checkout `pnpm dev` picks changes up. In the release package, run the installer again (`install.bat` / `install.sh`), which rebuilds the app, then restart the app.
</Callout>

## Plugin shape
```tsx
'use client';

import type { FrontendPlugin } from '@/lib/plugins/types';

const plugin: FrontendPlugin = {
  name: 'my-plugin',
  version: '0.1.0',
  enabled: true,
  bootstrap: (ctx) => {
    ctx.logger.info('plugin booted');
    return () => ctx.logger.info('plugin cleaned up');
  },
  slots: {
    global: ({ ctx }) => <div className="fixed bottom-4 right-4">Global UI</div>,
    'dashboard.nav': () => <a href="/dashboard/my-plugin">My plugin</a>
  },
  pages: [
    { path: '/dashboard/my-plugin', component: ({ ctx }) => <div>Plugin page</div> }
  ]
};

export default plugin;
```

<Callout type="info" title="Client-side plugins">
  Start plugin files with `'use client'`. Next.js can also render slot and page components on the server, so read `window`, `localStorage` or `ctx.storage` in effects or event handlers, not while rendering.
</Callout>

<Callout type="warn" title="Using app components">
  Plugins are compiled with the app, so they can import its UI components (`@/components/ui/*`) and page layout (`PageBody`, `PageHeader` from `@/components/app/page-header`). Only the plugin types and `ctx` are a stable plugin API; other app modules can change between releases.
</Callout>
