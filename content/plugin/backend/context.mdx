title: Backend Plugin Context
description: Everything the backend ctx object gives a plugin.

`register(ctx)` receives one `PluginContext`. Every plugin gets the same object, and plugins share the live Express app, routers, models and services.

## Routers

| Router | Mounted at | A route `'/plugins/status'` answers | Body parsed |
| --- | --- | --- | --- |
| `ctx.routers.api` | `/api` | `/api/plugins/status` | Yes |
| `ctx.routers.dashboard` | `/api/dashboard` | `/api/dashboard/plugins/status` | Yes |
| `ctx.routers.purchase` | `/api/purchase` | `/api/purchase/plugins/status` | Yes |
| `ctx.app` (during `register`) | `/` | needs the full path, `/api/plugins/status` | No: add a parser |

`ctx.routers.purchase` is the checkout API the storefront calls (`POST /api/purchase/cart/checkout`, `POST /api/purchase/guest/checkout`), so plugins can add to it or run checks before it. See [Extending checkout](/docs/plugin/backend/routes#extending-checkout).

## Core

    Mongoose 9 models: `User`, `Product`, `License`, `File`, `Purchase`, `Blacklist`, `Dashboard`, `Log`.

    ```js
    const { Product, Purchase } = ctx.core.models;
    const product = await Product.findOne({ slug: 'my-product' }).lean();
    ```

    - `File.path` holds only the file name in 2.0. The file is in the storage folder (`STORAGE_DIR`, default `api/storage`). Records uploaded before 2.0 keep an absolute path, and only its last segment counts.

    - `ctx.core.models.User.base` is the API's Mongoose instance. Use it to define your own models (see [Dependencies](/docs/plugin/backend/overview#dependencies)).

## Modules

`ctx.modules.purchase` is `{ router, webhook, coinbaseWebhook, paypalWebhook }`. `router` is the same object as `ctx.routers.purchase`.

<Callout type="warn" title="Webhook handlers can't be replaced">
  The payment webhook routes are registered before plugins load, so assigning a new function to `ctx.modules.purchase.webhook` (or the Coinbase and PayPal ones) changes nothing. To act on paid orders, use [`onPurchaseFulfilled`](/docs/plugin/backend/hooks).
</Callout>

## Examples

<Tabs items={['Add a route', 'React to fulfilled purchases', 'Patch a service']} defaultIndex={0}>
  <Tab>
    ```js
    module.exports = {
      name: 'status-endpoint',
      register(ctx) {
        // GET /api/plugins/status
        ctx.routers.api.get('/plugins/status', (_req, res) => {
          res.json({ status_overview: 'success', status_message: 'OK' });
        });
      }
    };
    ```
  </Tab>
  <Tab>
    ```js
    module.exports = {
      name: 'provisioner',
      register(ctx) {
        ctx.hooks.onPurchaseFulfilled(async (payload) => {
          for (const item of payload.items) {
            if (item.product.slug !== 'game-server-basic') continue;

            ctx.logger.info('provisioning server', {
              user: payload.user.email,
              product: item.product.slug,
              plan: item.plan,
              quantity: item.quantity
            });
          }
        });
      }
    };
    ```
  </Tab>
  <Tab>
    ```js
    module.exports = {
      name: 'stripe-tagger',
      register(ctx) {
        const sessions = ctx.services.stripe.checkout.sessions;
        const original = sessions.create.bind(sessions);
        sessions.create = (params, options) =>
          original({ ...params, metadata: { ...params.metadata, tag: 'plugin' } }, options);
      }
    };
    ```

    The checkout code calls the same Stripe instance, so the patch applies to every new card checkout, including subscriptions.
  </Tab>
</Tabs>

<Callout type="info" title="Preferred purchase integration point">
  If your plugin only needs to act after a checkout is paid, use `ctx.hooks.onPurchaseFulfilled(...)`. Patch payment services only to change what is sent to the provider.
</Callout>
